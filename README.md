# 小説エディタ

小説の本文を TXT で書くための、Tauri 2 製 Windows デスクトップアプリです。

## 開発

Windows に Node.js、pnpm 10.6.3、Rust の MSVC ツールチェーン、更新された Evergreen WebView2 を用意してください。文字数の集計には、この環境の `Intl.Segmenter` を使用します。

初回のみ依存関係をインストールします。

```powershell
pnpm install
```

開発用アプリを起動します。Vue、TypeScript、CSS の変更は自動で反映され、`src-tauri` の変更時は Tauri が再コンパイルされます。

```powershell
pnpm tauri dev
```

## 確認とビルド

コードを変更したら、次のコマンドで TypeScript の型検査と lint をまとめて実行します。型検査に失敗した場合は lint を実行せず終了します。

```powershell
pnpm check
```

保存形式、復元Storeの競合、検索・置換とUndo、書記素の統計、集計要求の順序、本文表示設定の回帰テストは `pnpm test` で実行します。テストはTauriのファイル入出力とWorker通信をメモリ上で代替し、利用者のTXTや復元データを変更しません。

配布用の Windows 実行ファイルとインストーラを生成するには、次を実行します。ビルド前に TypeScript の型検査も実行されます。

```powershell
pnpm tauri build
```

配布用の実行ファイルと NSIS インストーラは `src-tauri/target/release/` に生成されます。

## 第三者ライセンス通知と配布

Rust の通知生成には `cargo-about` 0.9.2 を使います。初回のみ次を実行してください。

```powershell
cargo install --locked --version 0.9.2 --features cli cargo-about
```

依存関係を変更したときと Windows 版を配布する前に、次の順序で確認します。

```powershell
pnpm install --frozen-lockfile
pnpm notices
pnpm check
pnpm tauri build
```

`pnpm notices` は JavaScript の本番依存関係と Windows 向け Rust 依存関係から通知を再生成します。生成結果の [JavaScript 通知](THIRD_PARTY_NOTICES_JS.md) と [Rust 通知](src-tauri/THIRD_PARTY_NOTICES_RUST.html) は Git で管理し、依存関係を更新した際は差分を確認してください。通知生成時に本文が見つからない、または Rust に未許可のライセンスが加わった場合は生成が失敗します。

配布物には本アプリの `LICENSE` と両方の第三者通知が `licenses/` に同梱されます。インストーラを作成したら同梱を確認してください。Rust 通知内の `source code` リンクから各クレートの該当バージョンのソースを取得できます。MPL-2.0 のクレートについては、ソースの入手方法を含む条件を配布前に個別確認してください。通知の自動生成だけで全条件への適合を保証するものではありません。

## 操作

上部の「ファイル」メニューから「新規」「開く」「保存」「名前を付けて保存」を選びます。Ctrl+N、Ctrl+O、Ctrl+S、Ctrl+Shift+S でも操作できます。「名前を付けて保存」は毎回保存先を確認し、成功後はそのファイルを現在の文書として扱います。保存中にも本文を編集でき、書き込みに間に合わなかった変更は未保存のまま残ります。本文の Undo / Redo は Ctrl+Z / Ctrl+Y です。未保存のまま別の文書を開く、新規作成する、またはアプリを閉じる際には確認が表示されます。ファイル選択や破棄確認を取り消すと、現在の本文と復元候補を維持します。

「編集」メニューの「検索」（Ctrl+F）、「置換」（Ctrl+H）で独立した「検索・置換」ウィンドウを開き、検索欄または置換欄へ移動します。既に開いていれば同じウィンドウを前面へ移します。ウィンドウはサイズ変更でき、開いたまま本文を編集できます。前後検索、1件置換、全置換、大文字・小文字の区別、正規表現に対応します。検索は文末・文頭で折り返します。入力欄の Enter は次の一致へ移動し、本文と検索画面のどちらでも F3 / Shift+F3 で前後検索できます。入力欄で Shift+Enter を押すと改行を含む文字列を検索・置換できます。正規表現の置換では `$1`、`$2` などでキャプチャグループを参照できます。無効な正規表現や該当なしは検索画面に表示されます。Esc、「閉じる」、タイトルバーの閉じるボタンで本文に戻り、置換は本文と同じ Undo / Redo で取り消せます。検索条件は検索画面を閉じてもアプリ終了まで保持され、文書を切り替えると新しい本文を対象にします。文書の切替や終了確認中は検索・置換を停止し、アプリ終了時には検索画面も閉じます。保存・検索・置換の各コマンドはツールバーのカスタマイズでも追加できます。

未保存の本文は入力が1秒止まると、アプリのデータフォルダー内の `recovery.json` に復元候補として保存されます。元の TXT は自動上書きされません。異常終了後の起動時に「復元」または「破棄」を選べます。「復元」は保存先を持たない未保存文書として開き、保存時に元のファイル名を候補として示します。元ファイルのパスは復元データに保存しません。BOMと改行形式は復元後も維持します。

復元候補は直近の未保存セッション1件で、履歴バックアップではありません。通常保存で最新の本文が保存されたときや、新規作成・別文書を開く・終了時に変更を明示的に破棄したときに削除します。保存中に追加した編集は引き続き復元候補として保護します。入力停止から1秒が経つ前や復元データの書き込み中に異常終了した場合、その直前の入力は復元できないことがあります。復元データの読み書きに失敗した場合は通知されるため、通常の保存で本文を保護してください。

「設定」メニューの「折り返し設定」から、右端で折り返し・指定桁数で折り返し・折り返さない、を選べます。設定画面では桁数（初期値80）と、指定桁数の幅が窓より広い場合に横スクロールするか窓幅に合わせるかも選べます。初期状態では横スクロールを優先します。桁数は現在の書体によるおおよその表示幅です。

設定画面の「エディター → 本文表示」では、明朝体・ゴシック体・メイリオ、文字サイズ（12～48px、初期値18px）、行間（1.0～3.0倍を0.1刻み、初期値1.9倍）を変更できます。書体は選択時、数値はEnterまたはフォーカス移動で反映します。不正な数値は保存せず、エラーを表示します。本文・選択・編集履歴は変わりません。未インストールの書体は代替書体で表示します。

設定の変更は自動保存され、画面を閉じても保持されます。各項目の「初期値に戻す」と、設定画面のUndo / Redo（Ctrl+Z / Ctrl+Y）で変更できます。数値等の入力欄内では入力自体のUndo / Redoが優先されます。

### アプリデータの保存先

既定の保存先はWindowsがアプリ用に用意するAppData（通常は `%APPDATA%\com.noveleditor.desktop`）です。設定画面の「アプリ → データ保存先」から「保存先を変更」または「現在のデータを既定の保存先へ移動」を予約できます。保存先を変更すると、選んだフォルダー内に `novelEditor-data` を作成し、次回起動時に設定、`project-tree.sqlite3`、未保存本文の `recovery.json` を移動します。移行先の起動と各Storeの読み込みが確認されるまで、旧保存先のファイルは片付けません。保存先操作は設定のUndo / Redoや「すべて初期値に戻す」の対象外です。

旧保存先のファイル整理に失敗した場合は、設定画面に警告が表示されます。「片付けの自動再試行をやめる」を確認すると、次回以降の自動片付けだけを停止します。この操作でファイルは削除されず、旧保存先に残ります。解除後は別の保存先変更を予約できます。

すでに別の `novelEditor-data` フォルダーにデータがある場合は、設定画面の「その他の操作」から「既存のデータフォルダーを使用」を選びます。これはデータをコピー・統合せず、選択先の内容を次回起動から使う操作です。現在の保存先のデータは変更・削除されません。

カスタム保存先へのポインター `storage-location.json` はAppDataに残り、選択中の保存先情報だけを保持します。AppDataを削除してポインターを失った場合、アプリは既定の保存先で起動します。以前のデータを使うには、設定画面の「その他の操作」から「既存のデータフォルダーを使用」を選び、`project-tree.sqlite3` を含む既存の `novelEditor-data` フォルダーを指定してください。起動時に保存先を利用できない場合は、専用画面から再試行・変更予約の取消・既存フォルダーの再指定ができます。

下部に全文文字数、選択文字数、主カーソルの行・列を表示します。高さは一定で、狭い画面では行・列、全文文字数の順に省略します。「統計」から常に全文と選択の文字数・空白除外文字数・400字換算、選択範囲数、論理行数、現在位置を確認できます。

文字数は見た目の文字に近い書記素単位です。結合濁点、異体字セレクター、肌色付き絵文字、家族の絵文字等を1書記素として数え、改行は除きます。通常文字数には空白とタブを含み、空白除外ではUnicodeの空白文字も除きます。複数選択は各範囲を個別に数えて合計し、正規表現検索等で文字の一部だけが選択された場合も、その選択文字列を数えます。行・列は1始まりで、折り返しは行数に含めず、タブは1列、書記素内部のカーソルはその文字の列とします。400字換算は文字数÷400の目安で、改行や空きマスを含む原稿用紙の組版枚数、投稿先の規則とは異なります。

全文統計は入力が250ms止まると別スレッドで集計し、計算中は前回の値に「更新中」を表示します。選択移動だけでは全文を再集計しません。文書切替直後は前文書の値を消して集計します。長文性能は実際のTauri / WebView2で確認し、差分集計などは実用上の問題が確認された場合に将来検討します。

「ウィンドウ」メニューから最小化、最大化、縦方向・横方向の最大化、閉じるを操作できます。縦方向・横方向の最大化はタスクバーを除く画面領域に片方向だけ広げます。「常に手前に表示」はチェックを切り替えて利用でき、アプリを閉じると設定は保存されません。右上のウィンドウ操作ボタンも使えます。「ヘルプ」は現在、項目がありません。

TXT は UTF-8 として読み書きします。既存ファイルの BOM と改行形式（LF、CRLF、CR）は保存時に維持します。未編集のファイルを保存すると元のバイト列をそのまま書き戻します。異なる種類の改行が混在する文書を編集して保存した場合、新しい内容の改行は最初に見つかった形式に統一されます。

## プロジェクトツリー

左側の「プロジェクト」からツリーを作成して切り替えられます。最後に選択したプロジェクトは次回起動時に復元されます。ツリー右端をドラッグするか、境界にフォーカスして左右キーで幅を220～480pxに調整できます。Home / End キーで最小幅・現在の画面で使える最大幅へ変更できます。ツリー見出しのボタンで別ウィンドウへ分離でき、分離先のボタンまたはウィンドウを閉じる操作で元へ戻ります。幅と分離状態は次回起動時にも復元されます。TXT を登録すると、保存場所を変えずにツリーから開けます。通常の「ファイル → 開く」で選んだファイルは自動登録されません。同じ TXT を複数の場所へ登録することもできます。

ツリー内には仮想フォルダを作成でき、TXTファイルをツリー領域へドロップするとルートへ登録され、フォルダ行へドロップするとその中へ登録されます。複数ファイルを同時にドロップした場合、登録できるファイルは追加され、失敗したファイルだけまとめて通知されます。ファイルやフォルダはポインターでドラッグして、同じ階層内の順番を変えたり、フォルダ内へ移動したりできます。ドラッグ中はツリーの上下端で自動スクロールします。フォルダや登録を削除しても実ファイルは削除されず、登録情報だけが解除されます。参照先を開けない場合はツリー上で示され、既存ノードの参照先を再指定できます。別のプロジェクト由来の文書を開いたままプロジェクトを切り替えた場合は、文書を開いた元のプロジェクトへ戻る操作が表示されます。
