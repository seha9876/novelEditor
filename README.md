# 小説エディタ

小説の本文を TXT で書くための、Tauri 2 製 Windows デスクトップアプリです。

## 開発

Windows に Node.js、pnpm 10.6.3、Rust の MSVC ツールチェーン、更新された Evergreen WebView2 を用意してください。文字数の集計には、この環境の `Intl.Segmenter` を使用します。

初回のみ依存関係をインストールします。

```powershell
pnpm install
```

開発用アプリを起動します。Vue、TypeScript、CSS の変更は自動で反映され、`src-tauri` の変更時は Tauri が再コンパイルされます。

```powershell
pnpm tauri dev
```

## 確認とビルド

コードを変更したら、次のコマンドで TypeScript の型検査と lint をまとめて実行します。型検査に失敗した場合は lint を実行せず終了します。

```powershell
pnpm check
```

保存形式、復元Storeの競合、検索・置換とUndo、選択範囲内検索と遅延要求、ファイル名検索、ツリーのキーボード操作、空白・行番号表示、集中モード、行移動、日本語変換中の入力、書記素の統計、設定・プロジェクトの複数ウィンドウ連携の回帰テストは `pnpm test` で実行します。テストはTauriのファイル入出力とWorker通信をメモリ上で代替し、利用者のTXTや復元データを変更しません。フロントエンド単独のビルドは `pnpm build` で確認できます。

Rust側のDB整合性、ツリー操作、保存先移行のテストと書式検査は次を実行します。テスト用DBはメモリまたは一時フォルダーに作成します。

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
```

配布用の Windows 実行ファイルとインストーラを生成するには、次を実行します。ビルド前に TypeScript の型検査も実行されます。

```powershell
pnpm tauri build
```

配布用の実行ファイルと NSIS インストーラは `src-tauri/target/release/` に生成されます。

## 第三者ライセンス通知と配布

Rust の通知生成には `cargo-about` 0.9.2 を使います。初回のみ次を実行してください。

```powershell
cargo install --locked --version 0.9.2 --features cli cargo-about
```

依存関係を変更したときと Windows 版を配布する前に、次の順序で確認します。

```powershell
pnpm install --frozen-lockfile
pnpm notices
pnpm check
pnpm tauri build
```

`pnpm notices` は JavaScript の本番依存関係と Windows 向け Rust 依存関係から通知を再生成します。生成結果の [JavaScript 通知](THIRD_PARTY_NOTICES_JS.md) と [Rust 通知](src-tauri/THIRD_PARTY_NOTICES_RUST.html) は Git で管理し、依存関係を更新した際は差分を確認してください。通知生成時に本文が見つからない、または Rust に未許可のライセンスが加わった場合は生成が失敗します。

配布物には本アプリの `LICENSE` と両方の第三者通知が `licenses/` に同梱されます。インストーラを作成したら同梱を確認してください。Rust 通知内の `source code` リンクから各クレートの該当バージョンのソースを取得できます。MPL-2.0 のクレートについては、ソースの入手方法を含む条件を配布前に個別確認してください。通知の自動生成だけで全条件への適合を保証するものではありません。

## 操作

「ファイル → 最近開いたファイル…」では、プロジェクト未登録の原稿も含め、最近開いた・保存したTXTを最新20件表示します。ファイル名と保存場所で同名原稿を区別でき、クリック、上下キーとEnterで開き、Escで閉じます。ツールバーにも登録できます。既定のショートカットはありません。

通常のファイル選択、ツリー、Ctrl+P、履歴からの読込と、保存・別名保存に成功した原稿が先頭へ移動し、重複は残りません。開いている原稿を履歴から選ぶと、本文や編集履歴を作り直さず本文へ戻ります。取消や読込失敗では現在の本文と履歴順序を維持し、欠落・読込不可の理由を一覧内に表示します。履歴だけの保存に失敗した場合は通知し、成功した原稿の読込・保存は維持します。

履歴は既存SQLiteの独立テーブルへ絶対パスと並び順の情報だけを保存し、再起動後も保持します。本文やカーソル位置は含まず、起動時の自動再読込は行いません。各項目の「履歴から削除」や確認付きの「履歴をすべて消去」は実ファイルに影響しません。プロジェクトの削除や設定初期化でも履歴は消えず、アプリデータの保存先変更では履歴も引き継ぎます。

登録済みの原稿は「ファイル → プロジェクト内ファイルを開く」（Ctrl+P）からファイル名で探せます。現在のプロジェクトが初期対象で、「全プロジェクトを検索」に切り替えることもできます。全半角・英字の大小を区別しない部分一致で、ツリー順に最大100件と総一致件数を表示します。上下キーで選び、Enterまたはクリックで開き、Escで取り消します。プロジェクト名・仮想フォルダの階層・実パスで同名ファイルや複数登録を区別できます。本文検索やディスク走査は行いません。検索語と対象範囲は開くたびにリセットされ、他プロジェクトの原稿を開いても表示中のプロジェクトは切り替わりません。未保存確認を取り消すと、現在の本文と復元候補を維持します。読込失敗は検索画面内に表示します。ツールバーにも登録できます。

長い本文の指定位置へ移動するには「編集 → 行へ移動」（Ctrl+G）を使います。現在行を初期表示し、1～総行数の行番号を入力してEnterまたは「移動」で、その論理行の先頭へ移動します。折り返しは行数に含めず、本文とUndo履歴は変わりません。Escまたは「キャンセル」で位置を変えずに戻れます。ツールバーのカスタマイズにも追加できます。

上部の「ファイル」メニューから「新規」「開く」「保存」「名前を付けて保存」を選びます。Ctrl+N、Ctrl+O、Ctrl+S、Ctrl+Shift+S でも操作できます。「名前を付けて保存」は毎回保存先を確認し、成功後はそのファイルを現在の文書として扱います。保存中にも本文を編集でき、書き込みに間に合わなかった変更は未保存のまま残ります。本文の Undo / Redo は Ctrl+Z / Ctrl+Y です。未保存のまま別の文書を開く、新規作成する、またはアプリを閉じる際には確認が表示されます。ファイル選択や破棄確認を取り消すと、現在の本文と復元候補を維持します。

「編集」メニューの「検索」（Ctrl+F）、「置換」（Ctrl+H）で独立した「検索・置換」ウィンドウを開き、検索欄または置換欄へ移動します。既に開いていれば同じウィンドウを前面へ移します。ウィンドウはサイズ変更でき、開いたまま本文を編集できます。前後検索、1件置換、全置換、大文字・小文字の区別、正規表現に対応します。検索は文末・文頭で折り返します。入力欄の Enter は次の一致へ移動し、本文と検索画面のどちらでも F3 / Shift+F3 で前後検索できます。入力欄で Shift+Enter を押すと改行を含む文字列を検索・置換できます。正規表現の置換では `$1`、`$2` などでキャプチャグループを参照できます。無効な正規表現や該当なしは検索画面に表示されます。Esc、「閉じる」、タイトルバーの閉じるボタンで本文に戻り、置換は本文と同じ Undo / Redo で取り消せます。検索条件は検索画面を閉じてもアプリ終了まで保持され、文書を切り替えると新しい本文を対象にします。文書の切替や終了確認中は検索・置換を停止し、アプリ終了時には検索画面も閉じます。保存・検索・置換の各コマンドはツールバーのカスタマイズでも追加できます。

未保存の本文は入力が1秒止まると、アプリのデータフォルダー内の `recovery.json` に復元候補として保存されます。元の TXT は自動上書きされません。異常終了後の起動時に「復元」または「破棄」を選べます。「復元」は保存先を持たない未保存文書として開き、保存時に元のファイル名を候補として示します。元ファイルのパスは復元データに保存しません。BOMと改行形式は復元後も維持します。

復元候補は直近の未保存セッション1件で、履歴バックアップではありません。通常保存で最新の本文が保存されたときや、新規作成・別文書を開く・終了時に変更を明示的に破棄したときに削除します。保存中に追加した編集は引き続き復元候補として保護します。入力停止から1秒が経つ前や復元データの書き込み中に異常終了した場合、その直前の入力は復元できないことがあります。復元データの読み書きに失敗した場合は通知されるため、通常の保存で本文を保護してください。

「設定」メニューの「折り返し設定」から、右端で折り返し・指定桁数で折り返し・折り返さない、を選べます。設定画面では桁数（初期値80）と、指定桁数の幅が窓より広い場合に横スクロールするか窓幅に合わせるかも選べます。初期状態では横スクロールを優先します。桁数は現在の書体によるおおよその表示幅です。

設定画面の「エディター → 本文表示」では、明朝体・ゴシック体・メイリオ、文字サイズ（12～48px、初期値18px）、行間（1.0～3.0倍を0.1刻み、初期値1.9倍）を変更できます。書体は選択時、数値はEnterまたはフォーカス移動で反映します。不正な数値は保存せず、エラーを表示します。本文・選択・編集履歴は変わりません。未インストールの書体は代替書体で表示します。

「表示 → 空白・タブを表示」または設定画面の「エディター → 本文表示」で、半角空白を点、全角空白を薄い枠、タブを矢印で表示できます。初期値はOFFで、以前の設定に項目がない場合もOFFです。表示を切り替えても文字幅・本文・コピー内容・検索・文字数・Undo履歴は変わりません。設定は自動保存され、次回起動、設定のUndo / Redo、初期値へのリセットに対応します。ツールバーにも登録できます。

ツールバーはアイコン操作専用です。設定画面の「外観 → ツールバー」で追加できる機能はすべてアイコンで表示され、本文の書体・文字サイズの直接入力は含まれません。文字サイズは増減アイコンで1pxずつ、行間は増減アイコンで0.1倍ずつ変更できます。どちらも設定画面の「エディター → 本文表示」では従来どおり直接指定できます。ツールバーの高さは極小（32px）・小（40px）・中（48px）・大（56px）から選べ、ボタンはそれぞれ24px・32px・40px・48pxです。

設定画面の「外観 → ステータスバー」では、下部へ表示する項目を追加・削除し、ドラッグまたは上下ボタンで順序を変更できます。ステータスバーを右クリックして「ステータスバーをカスタマイズ…」を選ぶと、この設定画面を直接開けます。現在のステータスバー一覧は上から順に、実際のバーでは右端から左へ表示します。全文文字数、選択文字数、現在位置（行・列）、総行数、フォント名、文字サイズ、行間、折り返し方式、統計ボタンを選べます。初期状態は全文文字数、選択文字数、現在位置、統計ボタンです。選択範囲がない場合、選択文字数は表示されません。統計集計エラーは項目設定にかかわらず通知されます。

設定の変更は自動保存され、画面を閉じても保持されます。各項目の「初期値に戻す」と、設定画面のUndo / Redo（Ctrl+Z / Ctrl+Y）で変更できます。数値等の入力欄内では入力自体のUndo / Redoが優先されます。

### 配色とプリセット

「設定 → 外観 → 配色」では、本文、検索強調、各バー、ツリー、設定画面、検索画面、メニュー、ダイアログの色を部位別に変更できます。カラーピッカーまたは `#RRGGBB` 形式のHEX入力を使い、各色の「戻す」で基準プリセットの色へ戻せます。OS標準の子ウィンドウのタイトルバーとファイル選択画面は対象外です。

配色の各行には適用先の説明があります。行にマウスを合わせるか、行内の入力欄へキーボードで移動すると、一覧上部の見本と実画面の表示中の代表箇所を白黒の枠で強調します。入力中の行が優先され、色や本文、Undo履歴は変更されません。見本では選択範囲・検索一致・ホバー・警告等の未表示の状態も確認できます。閉じたメニューや非表示の領域を自動で開くことはありません。行から離れる、ページを移動する、グループを折りたたむ、設定ダイアログを開く、設定窓を閉じると対象表示を解除します。

色は開いている各画面へ即時反映され、現在の配色として自動保存されます。再起動しても残りますが、保存済みのプリセットには「名前を付けて保存」または「上書き保存」を実行するまで反映されません。標準の「現行色・ダーク・セピア」は別名保存して編集版を作成できます。調整中に切り替える際は、保存・破棄・キャンセルを選べます。ユーザープリセットは名前変更・削除ができ、削除しても現在の色は残ります。配色操作も設定のUndo / Redoで戻せます。「すべて初期値に戻す」は現在の色だけを現行色へ戻し、保存済みプリセットは残します。

ピッカーの連続操作は、色見本とHEX表示をすぐ更新し、各画面への反映・通知を描画フレーム単位で最新色へまとめます。本文の折り返し再設定やアウトライン再解析、プリセット一覧の再送は行わず、変更したCSS変数だけを更新します。背景窓でも最終色の反映を止めず、通常の保存は最後の変更から250ms後です。操作の確定・ページ移動・終了時には保留入力を送り、終了前にメイン窓への反映を確認します。通信を確認できない場合はエラーを表示し、設定窓を残します。保存失敗時は保存済みの配色へ戻り、古い入力や通知で復元結果を上書きしません。

「エクスポート」は選択した保存済みプリセット1件をJSONファイルに書き出します。「インポート」は共有されたJSONを検証して一覧へ追加し、適用は一覧から選んで行います。同名の登録は連番で区別します。共有ファイルにはプリセット名と配色だけを含め、本文やファイルパスは含めません。

### アプリデータの保存先

既定の保存先はWindowsがアプリ用に用意するAppData（通常は `%APPDATA%\com.noveleditor.desktop`）です。設定画面の「アプリ → データ保存先」から「保存先を変更」または「現在のデータを既定の保存先へ移動」を予約できます。保存先を変更すると、選んだフォルダー内に `novelEditor-data` を作成し、次回起動時に設定、`project-tree.sqlite3`、未保存本文の `recovery.json` を移動します。移行先の起動と各Storeの読み込みが確認されるまで、旧保存先のファイルは片付けません。保存先操作は設定のUndo / Redoや「すべて初期値に戻す」の対象外です。

旧保存先のファイル整理に失敗した場合は、設定画面に警告が表示されます。「片付けの自動再試行をやめる」を確認すると、次回以降の自動片付けだけを停止します。この操作でファイルは削除されず、旧保存先に残ります。解除後は別の保存先変更を予約できます。

すでに別の `novelEditor-data` フォルダーにデータがある場合は、設定画面の「その他の操作」から「既存のデータフォルダーを使用」を選びます。これはデータをコピー・統合せず、選択先の内容を次回起動から使う操作です。現在の保存先のデータは変更・削除されません。

カスタム保存先へのポインター `storage-location.json` はAppDataに残り、選択中の保存先情報だけを保持します。AppDataを削除してポインターを失った場合、アプリは既定の保存先で起動します。以前のデータを使うには、設定画面の「その他の操作」から「既存のデータフォルダーを使用」を選び、`project-tree.sqlite3` を含む既存の `novelEditor-data` フォルダーを指定してください。起動時に保存先を利用できない場合は、専用画面から再試行・変更予約の取消・既存フォルダーの再指定ができます。

下部のステータスバーには、設定画面で選んだ項目を保存順（実表示の左端から右端）に表示します。設定画面の一覧ではこの順を反転し、上から右端・下へ行くほど左側に対応します。長いフォント名は省略されますが、カーソルを合わせると全文を確認できます。高さは一定で、狭い画面でも本文領域を圧迫しないようステータスバーの左側（設定一覧の下側）から省略します。統計ボタンを表示している場合は、そこから全文と選択の文字数・空白除外文字数・400字換算、選択範囲数、論理行数、現在位置を確認できます。

文字数は見た目の文字に近い書記素単位です。結合濁点、異体字セレクター、肌色付き絵文字、家族の絵文字等を1書記素として数え、改行は除きます。通常文字数には空白とタブを含み、空白除外ではUnicodeの空白文字も除きます。複数選択は各範囲を個別に数えて合計し、正規表現検索等で文字の一部だけが選択された場合も、その選択文字列を数えます。行・列は1始まりで、折り返しは行数に含めず、タブは1列、書記素内部のカーソルはその文字の列とします。400字換算は文字数÷400の目安で、改行や空きマスを含む原稿用紙の組版枚数、投稿先の規則とは異なります。

全文統計は入力が250ms止まると別スレッドで集計し、計算中は前回の値に「更新中」を表示します。選択移動だけでは全文を再集計しません。文書切替直後は前文書の値を消して集計します。長文性能は実際のTauri / WebView2で確認し、差分集計などは実用上の問題が確認された場合に将来検討します。

「ウィンドウ」メニューから最小化、最大化、縦方向・横方向の最大化、閉じるを操作できます。縦方向・横方向の最大化はタスクバーを除く画面領域に片方向だけ広げます。「常に手前に表示」はチェックを切り替えて利用でき、アプリを閉じると設定は保存されません。右上のウィンドウ操作ボタンも使えます。「ヘルプ」は現在、項目がありません。

TXT は UTF-8 として読み書きします。既存ファイルの BOM と改行形式（LF、CRLF、CR）は保存時に維持します。未編集のファイルを保存すると元のバイト列をそのまま書き戻します。異なる種類の改行が混在する文書を編集して保存した場合、新しい内容の改行は最初に見つかった形式に統一されます。

## 推敲・長文執筆の補助

検索画面の「選択範囲に限定」で、その時点の連続した選択範囲だけを検索・置換できます。選択が空の場合や複数範囲の場合は指定できません。「現在の選択で範囲を更新」で対象を指定し直せます。対象行を表示しますが、実際の対象は指定した文字範囲です。前後検索・F3・ハイライト・1件置換・全置換に同じ範囲を使い、境界をまたぐ一致を除外します。正規表現の行頭・行末や先読みは全文の文脈で判定します。

検索による選択移動では対象を変えず、本文の編集・置換・Undo / Redoに合わせて境界を追従させます。境界位置に挿入した文字も対象に含みます。範囲を全部削除して空にした場合は検索・置換を停止し、自動で全文検索へ広げません。範囲を再指定するか限定を解除してください。

### Gitで履歴を記録・バックアップ

「ファイル → 履歴とバックアップ…」を使います。ツールバーにも登録できます。PCにGit for Windowsが必要です。未導入の場合は [Git公式ダウンロード](https://git-scm.com/downloads/win) からインストールしてアプリを再起動してください。Gitがなくても原稿編集と通常保存は使えます。

1. 「原稿フォルダーを選んで始める」で、原稿が入っている実際のフォルダーを選びます。追加登録と登録解除は上部の「フォルダーの操作」から行います。既存Gitの内部を選んだ場合は、選択した場所と実際の管理ルートの違いを確認します。原稿は移動せず、ツリーのプロジェクトとは独立して複数登録できます。
2. 「履歴を記録」タブで、保存済みTXTの追加・変更・削除から対象を選びます。「この記録のメモ」は省略でき、日時入りの記録名になります。未保存の本文がある場合は「保存して続ける」を推奨します。「保存済みの内容だけ記録・キャンセル」も選べます。通常保存の外部更新確認を維持し、保存後は一覧を見直して、もう一度記録してください。
3. 「バックアップ」タブの「バックアップ先を選ぶ」で、別ドライブの空フォルダーか、以前の保管用bareリポジトリを指定します。設定だけでは送信しません。「記録をバックアップ」で、現在の履歴の系列（ブランチ）の記録を送ります。保管専用の形式なので、TXTを直接開く場所ではありません。
4. 「過去の原稿」タブで記録とTXTを選ぶと、読み取り専用で確認できます。最新の記録を初期選択し、原稿が1件なら自動表示します。「別のファイルとして取り出す」は新規TXTへ出力し、既存ファイルや編集中の本文を上書き・切替しません。
5. 元フォルダーを失った場合は「バックアップからフォルダーを復元」を使います。候補が複数なら最新記録の日時・メモを確認して選び、新しいフォルダー名と親フォルダーを指定します。完全な出力先を確認してから「この新しいフォルダーへ復元」で明示実行します。既存フォルダーは上書きせず、Git履歴を含めて独立した複製を作ります。

画面上部では「現在の原稿」「このPCの履歴」「別の保存先のバックアップ」を別々に確認し、「次の操作」で今必要な対応を案内します。原稿ファイルへの保存、過去の状態を履歴に残す記録、記録を別の保存先にも残すバックアップは、それぞれ手動の操作です。「変更0件」でも履歴がない場合は、未記録として表示します。無題・別フォルダーの原稿はこのフォルダーの履歴対象外として扱い、外部更新・欠落・確認失敗があれば保存済みの表示より優先します。

現在の原稿が最新記録に収録されているかは、プレビューで選択した過去の記録とは独立して確認します。収録されていても、今の未保存の編集や、保存後の未記録変更まで含まれるとは限りません。「最新の記録はバックアップ済み」も記録だけに対する確認結果です。確認時点の対象範囲を表示し、原稿全体が安全という一括判定は行いません。除外設定などで対象に出ない原稿は「詳しい情報」で対応範囲を確認してください。

記録する変更がないときはメモ・記録者入力を隠し、既存履歴の確認や編集・保存へ案内します。入力値は保持し、タブ切替や案内からのタブ移動だけでは記録・送信を実行しません。同じフォルダーの再確認でもメモ・記録者入力と有効な選択を保持します。操作ボタンが無効な理由は近くに表示します。

Gitバージョン、ブランチ名、記録ID、記録者のメールや既存設定、技術的な対応範囲は「詳しい情報」で確認できます。記録できない場合は理由を案内します。表示更新の情報通知、操作成功、部分成功の注意、通常失敗を区別します。エラーは操作の説明・次にできる対処・展開できる詳細に分け、確認失敗を「変更なし」や「履歴なし」と扱いません。記録後の後処理失敗や復元後の登録失敗では、完了済みの内容を明示し、重複して作成しないよう案内します。

**通常保存はTXTを更新する操作、記録はローカルGitへ区切りを残す操作、バックアップはその記録を別の保存先へ送る操作です。** いずれも手動で、自動記録・自動送信はしません。画面で未保存・未記録・未バックアップを区別します。外部Gitツールを使った後は「再確認」を押してください。ドライブ未接続時は確認不能と表示し、原稿とローカル履歴は残ります。

アプリからの記録はTXTだけです。既存Gitの除外・属性・改行変換に従うため、履歴の改行が作業ファイルと異なる場合があります。取り出しはGitに記録されたバイト列をそのまま出力します。UTF-8でない履歴はプレビューできない理由を表示し、バイト列の取り出しは可能です。履歴は50件ずつ追加表示します。記録者の名前とメールは既存Git設定を優先し、未設定分だけこの機能で補います。メール省略時は `writer@localhost` です。

ステージ済みの変更、競合、マージ・リベース等の処理途中、ブランチ未選択時には記録できません。他のGitツールで完了してから再確認してください。選択したTXTを一時インデックスで準備し、確認後の変更を検出して中止します。既存のステージや作業ファイルを一括リセットせず、ブランチを比較更新します。記録はコミットフックやコミット署名を実行せず、送信時のクライアント側フックも実行しません。署名・フックが必須の運用は既存Gitツールを使ってください。リンク、入れ子のリポジトリ、サブモジュール内部は記録対象外です。

バックアップには現在のブランチから到達できる過去の履歴が含まれるため、既存履歴に記録済みの画像等も送信されます。他のブランチ・タグ・未記録の変更・アプリ設定は含みません。強制送信はせず、保管先と履歴が分岐している場合は停止します。対応する送信先はローカルパスだけです。ブランチ操作・マージ・ネットワークURLへの送信・差分表示・現在の本文への直接復元は扱いません。

管理登録とバックアップ先・機能用の記録者情報はアプリのSQLiteへ保存され、アプリデータの保存先変更でも引き継ぎます。Git履歴本体は原稿フォルダーの `.git` と指定した保管先にあり、アプリデータ移行では移動しません。登録解除・プロジェクト削除・設定初期化でも原稿とGit履歴は消えません。復元・取り出し中のI/O失敗では不完全な出力が残る場合があります。Git処理中の終了要求には完了待ちを案内します。

### 外部で変更された原稿

現在開いているTXTは、メイン画面に戻ったとき、前面表示中の5秒間隔、保存直前にディスクの内容を確認します。操作中・終了中・無題の文書では定期確認しません。更新日時ではなく読み込んだバイト列を比較するため、同じ内容の再保存では通知せず、BOMや改行だけの変更も検出します。

外部変更を見つけると本文上部へ通知し、自動で本文を読み直すことはありません。「確認する」から「再読込」「名前を付けて保存」「現在の本文で上書き」「後で」を選べます。再読込は未保存の変更があれば破棄確認を挟み、成功すると本文・BOM・改行形式を更新し、編集履歴を初期化します。同じファイルのプロジェクトとの関連は維持します。「後で」は通知を残し、編集を続けられますが、保存時には再び内容を確認します。

外部内容への上書きには確認が必要です。確認中にさらに変更された場合は保存を止め、新しい状態で選び直します。ファイルが移動・削除された場合は、別名保存または確認付きの同じ場所への再作成を選べます。読取失敗は欠落と区別して理由を表示し、再確認・別名保存ができます。不正なUTF-8を再読込しても現在の本文は置き換えません。

Windowsでは、条件付き保存の内容検査から書込完了まで同じファイルハンドルを保持し、他プロセスによる書込・削除を拒否します。ロックできない場合は保存を中止します。新規ファイルは排他的に作成し、先に作成されたファイルを無条件には上書きしません。この機能は差分の自動統合やバックアップ世代の保存は行いません。

### 現在の原稿の履歴

### アウトラインと見出しの設定

アウトラインは現在の本文から、未保存の編集も含めて見出しを抽出します。「第一部」「第1章 再会」「第２節：翌朝」「第十二話」、単独行や空白／コロンでタイトルを添えた「プロローグ・エピローグ・序章・終章」を標準で認識します。半角・全角・漢数字に対応し、「第一章では……」のような本文や通常の番号列挙・装飾記号は拾いません。部＝レベル1、章・話・序章など＝2、節＝3で、存在する上位見出しの下に並びます。クリック／Enterで行頭へ移動し、矢印キーで移動・開閉できます。カーソルに対応する見出しを強調します。

「設定 → エディター → アウトライン」で、標準ルールの有効化・レベル変更、独自ルールの追加・編集・削除・並べ替えを行います。行頭／行末の文字、`第{番号}話` のような番号形式、詳細の正規表現とレベル1～6を指定できます。前後の空白を除いた一行ごとに判定し、上のルールを優先します。例文プレビューで確認し、不正・入力途中・時間超過の判定は保存しません。本文の記法の変更や見出しの挿入は行いません。ルールはアプリ共通で、設定のUndo／Redo・自動保存・保存失敗時の復元・標準へ戻す・全設定初期化に対応します。本文とルールの変更後200msにWorkerで解析し、世代が一致しない位置へは移動しません。本文・検索結果・履歴本文は設定やDBに保存しません。

左側の「プロジェクト」からツリーを作成して切り替えられます。最後に選択したプロジェクトは次回起動時に復元されます。ツリー右端をドラッグするか、境界にフォーカスして左右キーで幅を220～480pxに調整できます。Home / End キーで最小幅・現在の画面で使える最大幅へ変更できます。ツリー見出しのボタンで別ウィンドウへ分離でき、分離先のボタンまたはウィンドウを閉じる操作で元へ戻ります。幅と分離状態は次回起動時にも復元されます。TXT を登録すると、保存場所を変えずにツリーから開けます。通常の「ファイル → 開く」で選んだファイルは自動登録されません。同じ TXT を複数の場所へ登録することもできます。

ツリー内には仮想フォルダを作成でき、TXTファイルをツリー領域へドロップするとルートへ登録され、フォルダ行へドロップするとその中へ登録されます。複数ファイルを同時にドロップした場合、登録できるファイルは追加され、失敗したファイルだけまとめて通知されます。ファイルやフォルダはポインターでドラッグして、同じ階層内の順番を変えたり、フォルダ内へ移動したりできます。ドラッグ中はツリーの上下端で自動スクロールします。フォルダや登録を削除しても実ファイルは削除されず、登録情報だけが解除されます。参照先を開けない場合はツリー上で示され、既存ノードの参照先を再指定できます。別のプロジェクト由来の文書を開いたままプロジェクトを切り替えた場合は、文書を開いた元のプロジェクトへ戻る操作が表示されます。

メイン画面・分離ウィンドウのツリーでは、上下キーで表示行を移動し、Home / Endで先頭・末尾へ移動できます。右キーはフォルダを展開し、展開済みなら最初の子へ移動します。左キーはフォルダを折りたたみ、折りたたみ済みの行やファイルでは親へ移動します。移動だけでは原稿を開かず、Enterでファイルを開くかフォルダを開閉します。Shift＋上下で範囲選択、Ctrl＋上下で選択を変えずにフォーカス移動、Ctrl＋Spaceで選択を切り替えられます。Tabはフォーカス行とその操作ボタンへ移動します。折りたたみや登録解除で行が消えた場合は表示中の親または近隣行へ移り、空のツリーにもフォーカスできます。入力欄・IME変換中・処理中はこれらのツリー操作を行いません。
